# Flint SFT data (coding reasoning + execution-feedback tool use)

Files: `train.jsonl` (2144 ex, 4,423,556 tokens, 3,555,872 trained), `val.jsonl` (150 ex, 300,576 tokens), `messages_sample.jsonl` (20 raw examples), `maskcheck.log` (decoded mask check), `build/` (scripts that produced everything).
Each line: `{"src","ids","mask"}`. mask=1 on assistant output only: reasoning `<think>..</think>`, answer, `<tool_call>` blocks, plus the appended `<|end_of_text|>`. `<|assistant|>` header, system/user/tool-result and tool-definition tokens are mask=0.

## Rendering (from chat_template.jinja, HF-style jinja env with trim_blocks/lstrip_blocks)
- Assistant turn = `<|assistant|><think>{reasoning_content}</think>{content}<tool_call>name<arg_key>k</arg_key><arg_value>v</arg_value></tool_call>`. Tool results = `<|observation|><tool_response>..</tool_response>`. Tools are announced in a second `<|system|># Tools ...` block after the system message.
- The template emits NO end-of-turn token and NO BOS. We append `<|end_of_text|>` (id 150001) after every assistant turn (trained), including intermediate tool-call turns, so the model learns to stop after `</tool_call>`. No BOS is prepended. Re-rendered history at inference has no EOS between turns (template behaviour), a small train/inference mismatch.
- Generation prompt is bare `<|assistant|>`; the model must open `<think>` itself (train examples do).

## Verification and filters
- Code-reasoning traces keep only those whose extracted final python code **passes all public tests + up to 6 private/generated tests** when executed locally (stdout compared line-wise, 5 s/test; codeforces: only `problem_type=diff`). OpenCodeReasoning problems were joined to deepmind/code_contests tests by normalized problem text; unjoined rows dropped. OCR shards 0-9 scanned (later shards mostly repeat problems), codeforces py configs fully scanned.
- Pre-filters: finish_reason=stop, one `<think>` block >=200 chars, <=2 code fences, generation <=2700 tokens (drop, never truncate).
- Verified rows: 5,379 (codeforces 544 + OCR 4,835). Dropped after: non-English 4, repetition 3, garbled 0, near-dup problem text (5-gram Jaccard>=0.7) 80, exact-dup problem 2,094. Pool = 3,169 distinct problems (539 codeforces, 2,630 OCR).
- Decontamination vs HumanEval+ and MBPP+ (prompt + canonical solution): word-level lowercase 13-gram overlap dropped 29 examples; benchmark function name + 8-gram docstring overlap dropped 0.
- Selection: shortest examples first until train tokens <= 4.5M (the token cap, not supply, set the final size); each example <= 3072 tokens. Random 150 held out as val (same mix).

## Agentic data (deviation from plan)
Real SWE trajectories (nebius/SWE-agent-trajectories, SWE-Gym OpenHands, SWE-smith) were evaluated and rejected: shortest trajectories are >=18k chars (>5k tokens with the tool prompt), none fit the 3072 cap, and SWE-smith trajectories are Claude-generated. The agentic share is instead **synthesized execution-feedback trajectories from verified problems**: user problem -> think + `run_python(code, stdin)` call(s) on 1-2 public sample inputs -> real stdout from our local execution as `<tool_response>` -> final answer with code. Code and reasoning are the dataset's R1 traces; only the tool wrapper text ("Let me run the solution on the sample input.", "The program's output matches the expected sample output.") is ours. Tool: `run_python`, args `code`, `stdin`. Tool-call turns carry reasoning_content; the final turn does not.

## Caveats
- Only 2,144 train examples: 3,000 examples cannot fit in 4.5M tokens because verified short traces average ~2k tokens; the 4.5M cap was prioritized.
- Mostly Python competitive programming (Codeforces/AtCoder/etc.); no other languages. R1-style long "Okay, let's see" reasoning.
- Verification ran on macOS system python 3.9 (`/usr/bin/python3`).
